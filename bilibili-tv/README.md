# Bilibili TV

A Bilibili client (logged out) for the YuzukiNeko: a home page of cover cards with the tabs
"recommend" and "popular", a search page with an on-screen keyboard and a pinyin input method, and
the player of NekoBox for the 360P MP4 of a video (its `player*.c` are compiled from `../nekobox`,
not copied).

Build: `west build -b yuzukineko -d build/bili zephyr-components/bilibili-tv`

## What it does

- **Home**: 4 columns of cards (cover, two lines of title, uploader, number of views, duration).
  The recommendations and the popular list load 20 videos per page; the next page comes by itself
  when the end is near, up to 100 videos per list.
- **Cover**: the image server resizes (`@236w_133h_1c.jpg`); the video engine decodes baseline 4:2:0
  JPEGs, the others (the server sends 4:4:4 now and then) are decoded in software. Three threads
  fetch, the cache keeps 24 covers (`BILI_COVER_CACHE`), the lists hold the covers of the cards that
  are on the screen and one screen around it. While a video plays the cache is thrown out: the
  decoder needs the memory.
- **Search**: the field opens the keyboard, `lv_ime_pinyin` types Chinese one syllable at a time
  (the dictionary `src/ui/pinyin_dict.c` is generated by `tools/make_pinyin_dict.py`, characters by
  frequency), a row of trending words can be tapped. Results come in pages like the other lists.
  A search result has no `cid`, it is asked for (`/x/player/pagelist`) before the play address.
- **Player**: a tap opens the player page at once, shows the download (the file is kept in
  `/SD:/bilibili/<BV>.mp4` and reused), plays it, and comes back to the page it started from.
- **Danmaku**: the worker fetches `x/v1/dm/list.so?oid=<cid>` (raw deflate XML, `src/net/inflate.c` streams it,
  `src/api/danmaku.c` keeps scrolling/top/bottom comments, 8000 items at most) before the download; a failure
  only means no comments. `src/ui/ui_danmaku.c` moves a pool of 20 labels over the video from the player
  position (scrolling ones at a fixed speed in lanes, top/bottom ones for 4 s); the button "弹幕" on the
  player bar switches them, `bili dm [on|off]` prints the counters. While the player page is shown the UI
  thread runs at priority 8 (below the video thread) and at 25 Hz: at priority 6 the redraws cost 2-10 late
  pictures per 5 s, at 8 it is 0-1. `BILI_DM_FETCH=n` removes the fetch and the layer.
- **XIP**: the image runs from the SPI NOR window like NekoBox (`CONFIG_XIP`, overlay `xip_flash`, decoder and
  AAC code relocated to RAM by `BILI_HOT_RAM`): 5.1 MB of text and rodata (font, WiFi firmware) stay in the
  flash, about 10 MB of RAM are free before a video. Development flow: write `zephyr.bin` at flash `0x80000`
  (this replaces NekoBox there), run `xip-boot_fel.bin` from RAM:
  `xfel spinor write 0x80000 zephyr.bin; xfel write 0x20000 xip-boot_fel.bin; xfel exec 0x20000` after a
  relay cycle. No boot stub is written. `VDEC_SUNXI_MAX_MEMORY_KB=6144`: with 4300 the video stood still at
  100-400 ms (the audio went on) on some streams.
- **Font**: Noto Sans SC (SIL OFL), cut by `tools/make_font.py` to GB2312, the kana and the
  punctuation (2.2 MB, `src/ui/fonts/`), linked into the image; there is no font file on the card.

## What is needed on the card

- `/SD:/wifi.cfg`: the network name on the first line, the password on the second (the file NekoBox
  uses). `bili wifi` in the shell joins it again, `bili wifi <ssid> <psk>` joins another one.
- Videos are stored in `/SD:/bilibili/`.

## Network

Every request goes through the HTTP proxy `CONFIG_BILI_PROXY` (default `192.168.1.9:7897`; empty
for a direct connection, `bili proxy <host:port|off>` at run time). Plain requests are sent with
the full address, https ones through a `CONNECT` tunnel and a TLS handshake done in `src/net/http.c`
with mbedTLS (the certificate is not checked). Direct https uses the TLS socket of Zephyr.

On the test network the board is refused (RST during the handshake) by the Bilibili servers when it
connects directly, while a PC on the same router and the same public address is not; through the
proxy it works. Baidu and Taobao are reachable directly. The cause is not known (TCP options, DF and
the window of the SYN were tried and made no difference); the router is the suspect.

## Memory (16 MB)

The image is 10.4 MB (frame buffer 3 MB, font 2.2 MB, LVGL pool 0.75 MB, WiFi firmware 0.9 MB), the
rest is the malloc arena: about 5.6 MB free at the lists, 0.6 MB left with a 640x360 video playing.
The settings that had to be found out the hard way:

- `VDEC_SUNXI_MAX_MEMORY_KB=4300` and `NEKOBOX_VIDEO_STREAM_KB=256`: 11 pictures of 640x360. With 6
  the decoder stood still after the first picture, with 9 pictures were late all the time, the
  default (12288) does not fit.
- The network buffers: 192 x 512 bytes for receiving and a window of 16 KiB. With 64 x 128 bytes and a
  window of 32 KiB the packets were dropped and every loss cost a retransmission time out (a 10 KB
  cover took 2 s). `NET_MAX_CONN=48`: with 16 `connect()` answered ENOENT while covers were loaded.
- `AIC8800_MEM_POOL_KB=400`, `LV_Z_VDB_SIZE=10`, `LV_Z_MEM_POOL_SIZE=768 KiB`.

## Source layout

- `src/main.c`, `src/core/` — start, worker thread, CPU clock, the interface between the screens and the worker (`app.h`)
- `src/net/` — WiFi, HTTP/1.1 client (+TLS through the proxy), JSON, MD5, WBI signing, download thread, inflate
- `src/api/` — Bilibili calls (`bili_api`), answer parsers, danmaku XML reader
- `src/ui/` — screens (home, cards, search, player page, danmaku), covers, fonts, logo, pinyin dictionary
- `src/player/` — MP4/H.264/AAC player, a copy of the NekoBox one changed for a growing file
- `src/debug/` — self test and the freeze recorder (`crumbs.c`)
- `tools/` — generators of the font, logo and pinyin dictionary

## Self test

There is no shell. `-DCONFIG_BILI_SELFTEST=y` builds `src/debug/selftest.c`, which drives the UI by itself and
prints `selftest: ... PASS/FAIL` lines on the console: list loading, scrolling (waits for the covers, prints the
LVGL heap and the malloc arena), tab switch, searches with rare/emoji/long Chinese words, and playing
`CONFIG_BILI_SELFTEST_PLAYS` videos (position must advance). A watchdog thread dumps the threads when the UI
stalls. `CONFIG_BILI_HEARTBEAT` prints a status line every 10 s.

SD card: the TF slot stops answering when UART4 (PD6/PD7) is wired; leave it open. The standalone check is
`zephyr/samples/drivers/sdhc/sunxi_card`. The card is asked for again until it mounts.

## Checked on the board

Home with covers and titles, 30 fps playback of 640x360 with sound, streaming while downloading, the pinyin
input over the 8105 common hanzi, search, play of a result and the return to the list, the virtualized card grid
(the LVGL heap stays bounded while scrolling). Open: a rare freeze while stopping a long streaming download,
tearing warnings when the decoder runs out of spare pictures (`CONFIG_VDEC_SUNXI_H264_EXTRA_PICTURES`), the touch
panel itself was not tried with a finger.

## Later changes

- Streaming: the video plays while the file downloads (`src/net/download.c` thread, `player_open_growing` in the local player copy `src/player`); the bar shows the downloaded part; HTTP 5xx is retried 6 times; failures say why.
- Memory first: LVGL and the UI run from the flash window (`BILI_UI_RAM` is off by default), the card grid only keeps the widgets near the screen.
